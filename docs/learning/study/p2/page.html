The ideas

Percentiles and the tail

p95 is the time 95% of runs finish within; p50 is the median; the tail is the slow end. One huge run drags a mean, so artifacts 1, 2 and 5 publish none for skewed data.
Like
Your usual commute is p50; the day the bridge closed is the tail. Their average is no real day.
Matters
A1 publishes no p99 (at about 100 runs that is one or two runs); A7 publishes p99.99 because every run has at least 200 messages above it.

ECDF

One curve of every run: time across, share of runs finished by then up. Every percentile, and the tail, reads off it.
Like
Race results: at each clock time, the share of runners over the line.
Matters
A1's showed arm B's largest repeat-host run (148.2 s) beyond arm A's (111.6 s), despite B's lower median.

Spread versus interval

Spread is where single runs land. A 95% interval says how far the median itself moves between re-runs: a plausible range for the true median. A bootstrap imagines the re-runs: it redraws the runs with replacement, 10,000 times, and keeps the middle 95% of medians.
Matters
A1's arm A interval spans a stretch where no run landed and excludes a value where nine did.

Pre-registration

Commit the hypotheses, analysis, exclusions and stopping rule before the data exists. The git timestamp is the evidence.
Like
Sealing your prediction in an envelope before the match.
Matters
A1's predates its campaign data, not three paid reconnaissance captures, and says so; A6's campaign stays unread by its own rule.

Paired, interleaved runs

Run the arms close together in a shuffled order, so a slow hour or a drifting host hits every arm about equally. Arm A today, arm B tomorrow mixes the arm with the day.
Like
Weighing two parcels on one scale in the same minute: if the scale drifts, the difference survives.
Matters
A1 ran 100 shuffled triples, one run per arm; A5 ran both traffic patterns inside every server start.

Validation gate

A test, fixed in advance, that a model must pass against real runs before its answers count: pass, fail, or inconclusive (could not resolve its own margin; not a pass).
Like
Checking a new scale against known weights, and remembering it was only checked up to the heaviest.
Matters
A2's and A4's simulators had to match three real repeats in at least half the time bins; A5's synthetic adapters, real ones within ±5%.

Amendment versus forking path

A forking path is an analysis choice that depends on the data seen; unrecorded, no reader can discount it. An amendment is a dated, written rule change: what changed, why, what had been seen. One made after the data is still labelled post hoc.
Matters
A4's amendments are dated and say what had been seen: two came after its cell runs, before their analysis. A5's Amendment 3 extended its gate after an inconclusive verdict, and its post says so.

A failed gate is a result

Publish the failure and every miss, with what is known of the cause. Measured inputs stand; the model's numbers may appear, but only labelled unvalidated.
Matters
A2's simulator failed twice, 34 of 37 judged bins missed, then 37 of 37; A4's missed 10 of 13, so its GPU counts are not validated.

System views

From claim to trust

A composite of the artifacts, not one artifact's path: A1 had no model, so no gate. The boxes are the cards above: rules, spread, intervals, the gate, fair comparison.

  • A claim — e.g. one cache saves more than the other
  • Rules fixed first key step — pre-registration; later changes dated
  • Measured with spread — percentiles, ECDF, intervals
  • Model checked by gate key step — only where a model stands in; pass, fail or inconclusive
  • Compared fairly — paired, interleaved runs
  • Limits stated — what the result cannot claim
  1. A claim → Rules fixed first
  2. Rules fixed first → Measured with spread
  3. Measured with spread → Model checked by gate
  4. Model checked by gate → Compared fairly
  5. Compared fairly → Limits stated

Recall check

Answer out loud first, then open.

What does a 95% bootstrap interval on a median range over?

Medians of imagined re-runs of the experiment, not the runs themselves. It can cover a stretch where no run landed.

Same two clusters: why does 51/48 give a 5.00 s interval and 70/29 give 0.00 s? Must intervals shrink with more runs?

Near an even split a redrawn median can fall in either cluster, so the interval spans the gap; at 70/29 it almost never leaves the big one. Not necessarily: it shrinks only on average, and a new run can move the split toward even. A1's own data contradicted 'it shrinks as runs accumulate'.

Why don't 10,000 more resamples make an interval more trustworthy?

Resampling is free computation on the same runs; it adds no evidence. Only real runs, which cost GPU-hours, set the width.

Why is a failed gate a result, and what may you still conclude?

It is the pre-registered test answering no, which is its job. Measured inputs stand; model output appears only labelled unvalidated, and so does anything built on it.

What separates an amendment from a forking path?

The record: an amendment is dated in git and says what had been seen, so a reader can weigh it. Recording does not make a data-dependent change neutral, so one made after the data is labelled post hoc, like A1's first-touch rule.

Why interleave arms instead of running each in a block?

In blocks, drift over time lands on one arm and looks like its effect, inseparable afterwards. Interleaved, drift hits every arm about equally: it adds noise, not a bias.
